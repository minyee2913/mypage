# IGNOTUS

> 액션 속에서, 잠시 멈춰 생각하라

> 실시간 액션과 타일 전략 전투를 결합한 로그라이크 덱빌딩 액션 RPG

실시간 액션과 전략적인 타일 전투가 결합된 로그라이크 덱빌딩 액션 RPG. 전투 도중 시간을 멈추고 \[영역\]을 전개해 스킬을 타일에 배치한다. PC(Steam)와 모바일로 2027년 상반기 출시 예정.

## 프로젝트 소개

실시간 게임과 턴제 게임의 융합을 연구하면서 2025년 3월에 시작한 **1인 개발** 게임이다. 첫 커밋 다음 날 \[영역\](시간 정지) 시스템을 만들었고, 이후 카드·보드·멀티플레이·크로스플랫폼을 차례로 붙여 **PC(Steam)와 모바일(Android) 출시**를 준비하고 있다. 목표 출시 시기는 2027년 상반기다.

2D 픽셀 캐릭터가 코드로 조립한 3D 픽셀 지형 위에서 싸우는 2.5D 구성이다. 전투 중 \[영역\]을 펼치면 시간이 멈추고 플레이어 주변에 **7×7 타일**이 깔린다. 획득한 스킬을 원하는 타일에 배치하고 범위와 적 위치를 확인한 뒤 다시 실시간 전투로 돌아간다.

두 왕국 사이의 전쟁에서 패해 포로가 된 기사가 가까스로 탈출해 고향으로 돌아오지만, 왕국은 정체불명의 저주에 잠식되어 거대한 미궁이 되어 있다. 주인공은 미궁을 내려가며 저주의 원인과 남겨진 인물들의 이야기를 마주한다.

2026년 6월부터는 **Claude Code 같은 AI 코딩 에이전트**를 개발 과정에 적극적으로 활용하고 있다.

### 주요 특징

- 실시간 액션 + 타일 기반 전략 전투
- 전투의 시간을 멈추는 핵심 시스템 \[영역\]
- 원하는 위치에 직접 배치하는 다양한 스킬
- 스킬과 키워드의 상호작용을 활용하는 로그라이크 덱빌딩
- 무기 공격과 스킬을 연결하는 실시간 전투
- 플레이할 때마다 달라지는 스킬 조합과 빌드
- 저주에 잠식된 왕국과 그 안에 남겨진 인물들의 이야기
- 평상시와 전투 돌입 후 분위기가 변화하는 인카운터 연출

## 게임 플레이

- 에너지가 초당 10씩 차고, 100을 넘길 때마다 \[영역\] 전개 횟수가 1 쌓인다. 전투 중 \[영역\]을 펼치면 시간이 멈추고, 스킬을 타일에 끌어다 놓거나(또는 눌러서 추천 위치에 자동 배치) 발동한다.
- 무기 슬롯은 4개다. 슬롯마다 무기, 스크롤(영역 밖에서 쓰는 무기 능력), 스킬 목록이 묶여 있고, 무기를 바꾸면 대시와 강제 공격, 짧은 슬로 모션이 이어진다.
- 공격, 대시(대시 중 피격 시 피해를 무효화하는 회피, 쿨다운 10초), 방어(성공 시 반격 넉백)로 실시간 전투를 한다.
- 층에 들어갈 때마다 장점과 대가가 함께 붙은 저주 카드 3장 중 하나를 고른다(5층마다는 스킬을 주는 마녀 이벤트). 필드에 오래 머물면 미궁이 카드를 강제로 하나 더 붙인다.
- 층마다 보드에서 다음 방을 고르며 내려간다. 방 종류는 전투, 강적 전투, 이벤트, 보상, 상점, 휴식, 모루(스킬을 스크롤로 강화), 보스다.
- 층 구간은 하층(1~5층), 중층(6~10층), 상층(11~15층), 최상층(16~20층)으로 나뉜다. 구간을 끝까지 돌파한 무기 구성은 '낙인'으로 저장되어 다음 도전에 들고 갈 수 있다.

## 핵심 구현 기능

### \[영역\] 시간 정지 타일 스킬 시스템

실시간 전투 중 시간을 멈추고 7×7 타일 위에 스킬을 배치해 발동하는 핵심 전투 시스템.

**구현 목적**: 실시간 액션 안에 턴제·SRPG식 판단을 넣기 위해 만든 시스템으로, 프로젝트 시작 직후부터 게임의 중심이다.

**동작 방식**

- 전투 상태에서 \[영역\] 전개 횟수가 있으면 전개할 수 있다. 전개하면 **전역 시간 배율(Time.timeScale)을 0으로** 만들고, 애니메이터와 \[영역\] 카메라는 시간 배율의 영향을 받지 않게 바꾼다.
- 플레이어 주변에 4유닛 간격의 7×7 타일을 맵 보드 방향에 맞춰 깔고, 칸마다 아래로 레이를 쏴서 **지형 높이에 맞춘다**. 바닥이 없는 칸은 비활성화한다.
- 스킬을 타일에 끌어다 놓으면 스킬이 유효 칸 조건과 범위를 표시하고, 발동 시 에너지를 쓰고 효과를 실행한다. 누르기만 하면 스킬이 추천하는 칸에 자동 배치한다.
- \[영역\]을 닫으면 카메라와 시간을 되돌리고 실시간 전투로 돌아간다. 대시를 해도 \[영역\]이 닫힌다.
- 멀티플레이에서는 \[영역\]이 **최대 6초**로 제한되고, **다른 플레이어도 함께 멈춘다**. 일부 적과 보스도 자신의 \[영역\]을 펼친다.

**사용 기술**: Time.timeScale, Cinemachine, Raycast 지형 정렬, Netcode RPC

### 무기·스킬·스크롤 아이템 구조

ScriptableObject 상속 구조로 **스킬 108종, 스크롤 108종, 무기 19종**을 관리한다.

**동작 방식**

- 추상 Item(ScriptableObject) 아래에 SkillItem, ScrollItem, WeaponItem이 있고, 개별 아이템이 이를 상속해 동작을 채운다. 모든 아이템 에셋은 하나의 팩토리 데이터에 등록된다.
- 스킬은 등급, 비용, 쿨다운, 배치 가능 조건, 선택·발동 로직을 정의하고, 피격·대시·처치·필드 전환 같은 상황에 반응하는 패시브 훅을 가진다.
- 스크롤은 무기가 \[영역\] 밖에서 쓰는 능력이다. 스크롤마다 원본 스킬이 연결되어 있어 모루 방에서 스킬을 스크롤로 바꿀 수 있다.
- 공격 범위는 이름 붙은 범위(오프셋·크기·박스/구 형태)를 재사용하고 배율만 바꿔 쓴다. 적 공격은 바닥 경고 표시로 미리 알린다.
- 상태이상은 기절(치명타 확률 증가), 에어본(받는 피해 1.5배), 빙결(게이지 누적, 해제 시 저장된 피해 폭발), 화상이 있고 넉백과 8종의 가드 유형, 14종의 키워드가 있다.

**사용 기술**: ScriptableObject, 추상 클래스 / override, 코루틴

### 저주 카드와 런 구조

장점과 대가가 함께 있는 저주 카드, 층 구간, 방 선택 보드, 런 사이 성장으로 이어지는 로그라이크 루프.

**동작 방식**

- 저주 카드는 플레이어 강화와 적 강화를 함께 적용하는 클래스로, **일반 카드 49종과 해금형 카드 16종**이 있다. 가중치에 따라 3장을 뽑아 하나를 고른다.
- 해금형 카드는 기본 가중치가 0이고, 로비의 저주 메뉴에서 재화(골드바)로 해금하거나 카드 등장 가중치를 조절한다.
- 층마다 방 후보를 보드로 보여 주고, 방 가중치·등장 층 범위·최근 3개 방 제외 규칙으로 후보를 고른다.
- 런 사이에는 낙인(돌파한 무기 구성), 저주, 도감, 퀘스트(14종, 이벤트 기반 진행), 출석 보상이 이어진다. 층 구간별 최고 기록은 리더보드에 올라간다.
- 튜토리얼은 감옥 탈출부터 \[영역\] 전개, 마녀, 상점, 방 선택까지 단계별 입력 제한과 스포트라이트 안내로 진행하고, 컷신은 레터박스·타자기 자막을 쓰는 인게임 연출로 만들었다. 행사 시연용 데모 모드도 있다.

**사용 기술**: 가중치 랜덤, PlayerPrefs / JSON 저장

### ASCII 레이아웃 기반 절차적 방 조립

텍스트로 그린 방 레이아웃, 지역 테마, 시드로 지형 메시·충돌·소품을 코드로 조립한다.

**동작 방식**

- 방 레이아웃은 높이·바닥 재질·계단과 입구/출구/스폰/소품 표시를 문자 격자로 적은 텍스트다. 에디터 도구가 텍스트를 레이아웃 에셋으로 가져오고, 인스펙터에서 높이를 색으로 미리 본다.
- 레이아웃과 지역 테마, 시드로 **지형 메시와 충돌 메시, 소품을 한 번에** 만들고, 레이아웃을 무작위로 좌우 반전해 변화를 준다.
- 조립이 끝나면 **런타임에 NavMesh를 구워** 적 AI가 바로 길을 찾게 한다.
- 시드를 네트워크 오브젝트 ID에서 뽑아 **멀티플레이의 모든 참가자가 같은 방을 조립**한다.
- 원하는 방에서 바로 게임을 시작하는 방 테스트 창을 만들어 반복 작업을 줄였다.

**사용 기술**: Mesh 생성, NavMeshBuilder, Custom Editor

### 인카운터 연출과 저주 셰이더

전투가 시작되면 평온하던 방이 저주에 잠식되는 연출을 셰이더와 조명으로 만든다.

**동작 방식**

- 전투에 들어가면 필드 음악을 멈추고 시간을 0.1배로 늦춘 뒤 글리치 효과와 층 구간별 색 효과를 서서히 켠다.
- **전역 셰이더 값 하나**를 올리면 커스텀 URP 지형 셰이더가 노이즈 경계를 따라 '평온' 텍스처 아틀라스 위로 '저주' 아틀라스를 번지게 하고, 경계에 빛나는 줄기를 그린다.
- 같은 값으로 횃불 색, 환경광, 카메라 배경색도 함께 바꾸고, 전투가 끝나면 모두 되돌린다.
- 지형 셰이더는 SPUM 캐릭터의 픽셀 크기에 맞춘 텍셀 밀도로 포인트 샘플링하고, 정점 색 AO와 단계형 조명을 쓴다. URP Forward+를 지원한다.

**사용 기술**: HLSL, URP Forward+, Volume / 포스트 프로세싱

### 협동 멀티플레이 (개발 중)

Netcode for GameObjects로 LAN, 전용 서버, Steam 친구 접속을 모두 지원하는 협동 파티 플레이.

**동작 방식**

- 파티가 함께 낙인을 고르고 출발한다. 서버는 게임이 시작되면 참가자 명단을 잠그고, 명단에 있는 플레이어만 재접속을 허용한다.
- 접속 방식은 세 가지다: LAN 호스트(UDP 브로드캐스트로 방 검색), IP 직접 접속, 헤드리스 전용 서버(서버 빌드에서 카메라·화면 효과·터치 조작을 끔).
- Steam 친구 플레이를 위해 LAN(Unity Transport)과 Steam P2P(Steam Datagram Relay)를 한 방에서 동시에 받는 **복합 트랜스포트를 직접 만들었다**. 친구 전용 로비, 초대, Rich Presence 참가를 지원한다.
- **이동은 소유자 권한, 적 AI와 전투 진행은 서버 권한**으로 처리한다. 로딩·층·파티 준비·전투 상태 등은 NetworkVariable과 RPC로 동기화한다.

**사용 기술**: Netcode for GameObjects, Unity Transport, Steamworks.NET, Dedicated Server

**고려 사항**

- 온라인·LAN 통합 테스트는 아직 진행 중이다.

### PC·모바일 크로스플랫폼과 클라우드 저장

**하나의 코드베이스**에서 PC(Steam)와 Android(Google Play Games)를 함께 지원한다.

**동작 방식**

- Input System에 키보드·마우스, 게임패드, 터치 조작 체계를 두고, 모바일은 직접 만든 가상 조이스틱과 화면 버튼을 쓴다.
- 저장과 리더보드는 Android에서 Google Play Games(로그인, 저장 게임, 리더보드), PC에서 Steam(Cloud 저장, 리더보드)을 쓰도록 컴파일 조건으로 나눴다.
- 로컬 저장은 JSON을 백업 키부터 쓰는 이중 기록으로 남기고, 로컬과 클라우드 저장이 다르면 진행도 점수가 높은 쪽을 고른다.
- 모바일에서는 MSAA·SSAO·실시간 그림자를 끄고 해상도 긴 변을 1920으로 제한하며, 파티클 밀도를 낮춘다. 쓰지 않는 전체 화면 효과는 모든 플랫폼에서 꺼 둔다.

**사용 기술**: Input System, Google Play Games, Steamworks.NET, URP 설정 튜닝

### 픽셀 VFX 파이프라인

일반 파티클 이펙트를 게임의 픽셀 아트 톤에 맞추는 도구와 런타임 처리.

**동작 방식**

- 런타임에 파티클 텍스처를 저해상도·포인트 필터·단계 색으로 바꾼 사본을 만들어 픽셀 느낌을 낸다.
- 에디터 도구로 파티클 이펙트를 게임 카메라와 같은 40° 시점에서 픽셀 스프라이트 시트로 굽는다. **검은 배경과 흰 배경에 각각 렌더링해 알파를 복원**한다.
- 이펙트마다 오브젝트를 만들지 않고 방출만 하는 파티클 시스템을 쓰며, 프레임당 타격 수를 제한하고 데미지 숫자는 풀링한다.

**사용 기술**: ParticleSystem, RenderTexture, Editor 도구, Object Pooling

## 기술적 문제 해결

### 시간 정지 중 타일 선택이 엉뚱한 칸을 잡는 문제 [해결]

- 문제 상황: \[영역\]을 펼친 상태에서 마우스로 타일을 고르면 실제와 다른 칸이 선택됐다.
- 원인 분석: \[영역\] 중에는 시간 배율이 0이라 물리 갱신이 없고 Transform 자동 동기화도 꺼져 있어서, **타일을 옮긴 뒤에도 충돌체가 이전 위치에 남아 있었다**.
- 해결 과정:
  - **타일 선택을 물리 레이캐스트에 의존하지 않도록** 바꿨다.
  - 타일마다 그 타일 높이의 수평면과 마우스 광선의 교점을 구하고, 교점이 칸 안에 드는 타일 중 카메라에 가장 가까운 것을 고른다.
  - 범위 미리보기용 판정이 필요한 곳에서는 Transform 동기화를 직접 호출한다.
- 결과: 단차가 있는 지형에서도 **시간이 멈춘 상태로 정확한 칸**을 고를 수 있게 됐다.

### 시간이 멈춘 동안 연출과 연속 발사가 멈추는 문제 [해결]

- 문제 상황: \[영역\] 중에 나온 타일 연출 파티클이 멈춰 보이고, 연속 발사 스킬의 간격 대기가 시간 복귀 후 불안정했다.
- 원인 분석: 파티클과 WaitForSeconds가 모두 시간 배율의 영향을 받는데, \[영역\]은 시간 배율을 0으로 만든다.
- 해결 과정:
  - 파티클 시스템을 **시간 영향을 받는 것과 받지 않는 것 두 벌**로 두고, 시간이 멈춘 동안 나온 연출은 영향을 받지 않는 쪽으로 보낸다.
  - 연속 발사 간격은 직접 만든 타이머로 재고, 시간 정지 중에는 멈췄다가 풀리면 남은 시간을 이어서 쓴다.
- 결과: 시간 정지 중에도 연출이 자연스럽게 재생되고, 정지 전후로 연속 발사 간격이 유지된다.

### 모바일에서 지형이 통째로 사라지는 셰이더 문제 [해결]

- 문제 상황: PC에서는 정상인 커스텀 지형 셰이더가 모바일 기기에서 지형 전체를 그리지 못했다.
- 원인 분석: GLES3·Vulkan에서 **half(최소 정밀도) 값이 정수 연산에 섞이면 셰이더 컴파일이 실패**했다.
- 해결 과정:
  - 셰이더의 정밀도를 **전부 float로 통일**했다.
- 적용한 기술 / 접근: HLSL, URP
- 결과: 모바일에서도 지형이 정상적으로 그려진다.

### 지형이 분홍색으로 바뀌며 UI 위에 그려지는 문제 [해결]

- 문제 상황: 카메라와 캐릭터 사이를 가리는 물체를 반투명하게 만드는 가림 페이드 기능이 동작하면 방 전체가 분홍색으로 변해 UI 위에 그려졌다.
- 원인 분석: 방 지형 전체가 메시 하나라서 페이드 대상이 되면 방 전체가 **URP에서 지원하지 않는 레거시 투명 셰이더**로 바뀌고 투명 렌더 큐로 들어갔다.
- 해결 과정:
  - 방을 조립할 때 지형 메시에 페이드 제외 옵션(최종 알파 1 고정)을 붙였다.
- 결과: 벽·소품은 계속 페이드되고 지형은 정상 셰이더를 유지한다.

### LAN과 Steam P2P를 동시에 받을 때 연결 ID 충돌 [부분 해결]

- 문제 상황: 한 방에서 LAN 플레이어와 Steam 친구를 함께 받으려면 두 전송 계층의 연결 ID가 하나의 네트워크 세션 안에서 겹치지 않아야 했다.
- 원인 분석: **Unity Transport가 내부에서 Netcode의 ID 매핑을 직접 조회**하기 때문에, LAN 쪽 ID를 바꾸면 전송이 막힌다.
- 해결 과정:
  - LAN 쪽 ID는 그대로 넘기고, **Steam 쪽 ID만 LAN과 겹치지 않는 별도 범위**(하위 32비트를 모두 1로 채운 값)를 쓰도록 했다.
  - 호스트는 두 전송 계층을 동시에 열고, 클라이언트는 둘 중 하나로만 접속하는 복합 트랜스포트로 묶었다. Steam을 쓸 수 없는 환경에서는 기존 트랜스포트만 쓴다.
- 적용한 기술 / 접근: Netcode for GameObjects, Unity Transport, SteamNetworkingSockets
- 결과: LAN과 Steam P2P 접속을 한 세션에서 받는 구조를 구현했다.
- 남은 문제: 온라인·LAN 통합 테스트 항목은 아직 확인 중이다.

### 클라우드 저장이 빈 데이터로 덮어써질 위험 [해결]

- 문제 상황: 게임 시작 직후 아이템 데이터가 준비되기 전에 저장이 일어나면 빈 무기 목록이 저장되어 기존 진행이 사라질 수 있었다.
- 해결 과정:
  - **아이템 팩토리가 준비될 때까지(최대 15초) 저장을 막고**, 준비에 실패하면 계속 막아 둔다.
  - 로컬 저장은 백업 키부터 쓰는 이중 기록으로 남긴다.
  - 로컬과 클라우드(Steam Cloud, Google Play 저장 게임) 데이터가 다르면 무기 수·재화·최고 층으로 계산한 진행도 점수가 높은 쪽을 고른다.
- 결과: 로드가 끝나기 전의 저장 시도는 무시되고, 기기 간 저장 충돌도 진행도가 큰 쪽으로 정리된다.
