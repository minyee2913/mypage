# KOROSHITE

> 잊혀진 영웅들의 난투

> 8인 대전과 보스전을 지원하는 PC 멀티플레이 액션 게임 (2024 디지털콘텐츠개발대회 금상)

서로 다른 스킬을 가진 캐릭터로 8인 대전과 보스전을 즐길 수 있는 PC 액션 게임.

- 페이지: https://human.minyee2913.net/projects/koroshite
- 카테고리: 게임 개발
- 개발 기간: 2024.02
- 플랫폼: PC
- 장르: 대전, 멀티플레이, 액션, 스토리
- 팀 구성: 1인 개발
- 게임 엔진: Unity 6 (URP)
- 사용 언어: C#
- 프레임워크 / 라이브러리: Photon PUN 2, PlayFab, Cinemachine, DOTween
- 주요 기술: RPC, OnPhotonSerializeView, PlayFab 사용자 데이터, 코루틴 컷씬

## 프로젝트 소개

여러 세계에서 죽음을 맞이한 영웅들이 불가사의한 장소에 모여 사명을 잊고 싸운다는 설정의 멀티플레이 액션 게임이다.

컷씬과 다이얼로그로 스토리를 전개하고, 모두 다른 스킬을 가진 캐릭터로 8명이 함께하는 대전 모드와 혼자서도 할 수 있는 보스전을 제공한다.

기획부터 네트워크, 캐릭터·보스, UI까지 **혼자 개발**했고, 개발 도중 Unity 6로 프로젝트를 옮겼다.

### 주요 특징

- **1인 개발**, 2024 디지털콘텐츠개발대회 **금상**
- Photon PUN 기반 **최대 8인** 실시간 대전
- 스킬 구성이 모두 다른 **캐릭터 5종**
- 2페이즈 보스와 슬로 모션 반격 연출
- 온·오프라인 분기로 **싱글플레이도 같은 네트워크 코드**를 사용

## 게임 플레이

- 로그인 또는 회원가입(게스트 로그인 지원) 후 첫 시작 시 스토리 컷씬과 싱글플레이 튜토리얼이 진행된다. 튜토리얼은 건너뛸 수 있다.
- 로비에서는 캐릭터들이 NPC로 돌아다니고, 클릭하면 캐릭터와 스킬 정보를 볼 수 있다. 멀티플레이 방 목록과 싱글플레이 스테이지도 여기서 고른다.
- J 공격, K 스킬(누르고 있기), L 궁극기(에너지 소모), Shift 대시, 2단 점프로 싸운다.
- 데스매치는 5분 동안 처치 수로 순위를 매기고(동률이면 처치당한 수), 처치되면 5초 뒤 무작위 위치에서 부활한다. 게임 중 F로 캐릭터를 바꿀 수 있고, 남은 시간이 150초가 되면 서든 데스가 시작되어 에너지가 매초 차오른다.
- 1:1 듀얼은 2분 동안 체력 1.5배로 겨루며, 먼저 처치한 쪽이 이긴다.

## 설계 / 패턴

- Singleton: 매니저 클래스 관리
- Observer: RPC를 이용한 이벤트 기반 네트워크 동기화
- Strategy: 추상 Character 클래스를 상속해 캐릭터별 기능 구현
- Proxy: 온라인이면 RPC로, 오프라인이면 로컬로 호출하는 래퍼로 싱글플레이와 코드 공유
- Template Method: 추상 Monster 클래스로 몬스터 기본 행동(이동·피격·사망·넉백) 정의
- Builder: 체이닝으로 대사를 쌓는 다이얼로그 API
- 캐릭터 id 문자열로 프리팹을 불러와 생성

## 핵심 구현 기능

### PlayFab 계정과 캐릭터 보유 정보

**구현 목적**: 별도 서버를 구축할 시간과 비용이 없어 PlayFab API로 계정 정보를 저장하고 불러왔다.

**동작 방식**

- 이메일·비밀번호 로그인(LoginWithEmailAddress), 표시 이름을 포함한 회원가입(RegisterPlayFabUser), 게스트 로그인을 지원한다. 첫 로그인 때 표시 이름을 정하게 한다.
- 요청 전에 빈 칸을 검사하고, 성공·실패 콜백으로 결과를 처리한다.
- 튜토리얼 완료 여부와 보유 캐릭터를 PlayFab 사용자 데이터에 저장해, 로그인하면 튜토리얼 또는 로비로 보낸다. 사무라이와 파이터는 기본 제공한다.

**사용 기술**: PlayFab Client API

### Photon 기반 멀티플레이 동기화

**구현 목적**: 많이 써 봐서 익숙하고 빠르게 구현할 수 있는 Photon 네트워크로 멀티플레이를 구현했다.

**동작 방식**

- 로그인 → Photon 로비 → 방 목록 → 방 만들기(최대 8명)로 이어지고, 모드 선택과 시작은 방장만 할 수 있다. 경기마다 5초 카운트다운 후 시작 위치를 섞는다.
- OnPhotonSerializeView로 이름, 체력, 실드, 킬·데스, 바라보는 방향, 이동·달리기·착지·대시 상태를 주고받고, 위치는 PhotonTransformView로 맞춘다.
- 피해·회복·넉백·애니메이션 트리거처럼 한 번만 일어나는 일은 RPC로 전달한다.
- 공격 판정은 공격한 쪽 클라이언트에서 하고, 가드·무적 같은 피격 처리는 각 클라이언트가 맞은 캐릭터 기준으로 한다.
- 방장 권한으로 채팅 차단·강퇴·방장 넘기기를 할 수 있고, 관전 모드가 있다.

**사용 기술**: Photon PUN, RPC, OnPhotonSerializeView

### 캐릭터 5종

체력과 스킬 구성이 모두 다른 캐릭터를 추상 클래스 하나로 구현했다.

**동작 방식**

- **사무라이**(체력 800): 2연속 돌진 베기, 정면 공격을 막는 가드와 타이밍을 맞추면 발동하는 반격, 넓은 범위를 연속으로 베는 궁극기.
- **파이터**(체력 1000): 빠른 잽, 자세를 잡고 버티며 힘을 모아 차는 킥(모은 만큼 피해와 회복), 궁극기 동안 킥을 바로 쓸 수 있는 스택 8개.
- **시노비**(체력 650): 앞뒤를 연달아 베는 공격, 은신 돌진, 맞은 직후 잠깐 무적이 되는 회피.
- **뱀파이어 걸**(체력 1200): 자기 체력을 쓰며 공격하고, 연속 공격으로 강화된 할퀴기로 체력과 에너지를 빼앗는다. 궁극기는 적 하나를 삼켜 연속 피해를 준다.
- **뱀파이어 맨**(체력 600): 공격으로 실드를 쌓고, 실드를 써서 질주하며 적에게 표식을 남긴 뒤 표식을 터뜨린다.
- Player 오브젝트가 입력과 판정을, Character 오브젝트가 스킬과 애니메이션을 맡는다. 각 Character는 소유자의 Photon UserId로 자기 Player 밑에 붙는다.

### 보스 '기억의 환영'과 스토리 스테이지

**동작 방식**

- 튜토리얼 → 로비 튜토리얼 → 스테이지 → 보스전 순서로 진행되고, 컷씬은 코루틴으로 카메라 확대·말풍선·트윈을 순서대로 실행한다.
- 다이얼로그는 대사를 체이닝으로 쌓는 API로 만들었고, 타자 치듯 글자가 나오며 좌우에 초상화를 띄운다.
- 보스는 체력 40%에서 회복을 시전한 뒤 붉게 변해 2페이즈로 넘어가고, 표창·돌진, 멀리 떨어진 대상에게 순간이동하는 패턴을 쓴다.
- 보스는 무작위로 가드하고, 2페이즈 후반에는 가드에 성공하면 **슬로 모션(시간 배율 0.6)**과 함께 반격한다.
- 몬스터 AI는 소유자 클라이언트에서만 돌고 체력·방향·이동을 동기화한다.

**사용 기술**: Coroutine, DOTween, Time.timeScale

### 타격감 연출

**동작 방식**

- 카메라 흔들림, 넉백, 피격 시 하얗게 번쩍이는 효과, 대시 잔상을 조합해 타격감을 강조했다.
- 효과음은 내 캐릭터와 일정 거리(15) 안에서 난 소리만 재생해, 8명이 싸워도 멀리서 난 소리가 섞이지 않게 했다.
- 사무라이의 가드 반격은 공격자의 동작을 취소하고 밀쳐 내며 공격 쿨타임을 준 뒤, 카메라 흔들림·사운드·넉백과 회복을 코루틴으로 순서대로 실행한다.

## 기술적 문제 해결

### 캐릭터가 엉뚱한 플레이어에게 붙던 문제 [해결]

- 문제 상황: 멀티플레이에서 캐릭터 오브젝트가 다른 플레이어 밑에 붙는 경우가 있었다.
- 원인 분석: 캐릭터가 자기 주인을 이름과 클라이언트마다 따로 만든 난수로 찾고 있어서, 클라이언트끼리 같은 플레이어를 가리킨다는 보장이 없었다.
- 해결 과정:
  - 방을 만들 때 Photon UserId를 공개하도록 설정하고, 캐릭터 생성 데이터에 소유자의 UserId를 실어 각 클라이언트가 같은 기준으로 주인을 찾게 했다.
- 적용한 기술 / 접근: Photon UserId, PublishUserId
- 결과: 모든 클라이언트에서 캐릭터가 같은 플레이어에게 붙는다.

### 클라이언트마다 맵이 다르게 나오던 문제 [해결]

- 문제 상황: 같은 방에 있는 플레이어들이 서로 다른 맵에서 경기를 시작했다.
- 원인 분석: 맵을 각 클라이언트가 로컬에서 무작위로 고르고 있었다.
- 해결 과정:
  - 맵 관리자를 네트워크 오브젝트로 바꾸고, 정해진 맵 번호를 RPC로 모두에게 보내 같은 맵을 켜게 했다.
- 적용한 기술 / 접근: PhotonView, RPC
- 결과: 같은 방의 플레이어들이 RPC로 받은 같은 맵 번호로 시작한다.

### 싱글플레이에서도 네트워크 코드를 그대로 쓰기 [해결]

- 문제 상황: 스킬·피해 처리가 모두 RPC로 짜여 있어, 서버에 연결하지 않는 싱글플레이 스테이지에서는 그대로 쓸 수 없었다.
- 해결 과정:
  - RPC 호출을 래퍼 함수로 감싸, Photon에 연결되어 있으면 RPC를 보내고 아니면 같은 함수를 로컬에서 바로 부르게 했다.
- 적용한 기술 / 접근: Proxy 패턴
- 결과: 캐릭터·보스 코드를 멀티플레이와 싱글플레이가 함께 쓴다.
